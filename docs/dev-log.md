# 개발 일지

날짜는 실제 작업일, Step은 개발 계획상 단계다.

## 2026-09-29

### Step 1. 데이터 확보와 공통 스키마

- 데이터 출처 결정: 배경 대화는 AI Hub 한국어 SNS(실제 메신저 대화, 비식별화), 사건 증거는 합성
- 트러블슈팅: macOS unzip이 인코딩 표시 없는 한글 파일명을 깨뜨림 → 원래 바이트를 복원해 UTF-8/CP949 순으로 디코딩하는 해제 스크립트 작성
- 데이터 조사: 비식별화 표시 분포 확인(#@이름# 11만, #@시스템#송금# 295 등) → 합성 증거도 같은 표시 형식을 쓰기로 결정
- 공통 레코드 스키마와 AI Hub 스트리밍 어댑터 구현, 무결성 해시 변조 탐지 테스트 포함
- 트러블슈팅: venv 활성화 후에도 zsh 명령 캐시 때문에 전역 pytest가 실행됨 → hash -r, python -m으로 실행 통일
- 발견: 이름순 처리로 샘플이 한 주제에 쏠림 → 주제별 층화 추출 옵션 추가

### Step 2. 시나리오 1 설계와 합성 증거 생성

- 사건 시나리오 1(중고거래 사기, 개발용) 설계와 합성 증거 생성기 구현. LLM은 문장만 쓰고, 배치·시스템 메시지·정답지 기록은 코드가 담당
- 트러블슈팅: EXAONE이 존댓말 거래 대화에서 긴 문장과 이모지를 반복 → 프롬프트 강화 대신 결정적 후처리(문장부호 분할, 이모지 제거)로 해결
- 트러블슈팅: 시나리오가 LLM에게 금지된 시스템 표시를 쓰라고 지시하는 모순 발견 → event 장면 도입, 불러올 때 거부하는 검사 추가
- 사람 검수 3회: 증거 판정 11/3/4 → 14/3/1 → 15/3/0 (통과/애매/불합격). 사람이 찾은 오류(역할 뒤바뀜, 금지어, 가짜 표시, 맥락 대화의 정답 선점 등)를 매번 검사기 규칙으로 옮김
- 검수 통과 대화방은 유지하고 문제 대화방만 재생성하는 기능 추가(대화방별 독립 난수)
- 발견: 합성 메시지에 ㅋㅋ·ㅠㅠ 같은 자모가 0자(실제는 메시지당 약 0.94자) → 문체로 합성을 구분할 위험. 가상 기기 조립 단계에서 합성 오답 대화방 확대와 판별기 측정으로 대응 예정

### Step 3. 가상 기기 조립

- AI Hub 배경 대화 2,000개(상거래 300개 고정, 나머지 주제 균등)와 합성 대화방 7개를 한 대의 메신저 DB로 조립. 말투 예시로 쓴 대화 1,800개는 배경에서 제외
- 배경 대화 날짜는 하루 단위로만 옮겨 대화 안 시간 간격과 하루 중 시각 분포를 유지
- 출력을 에이전트가 보는 device/와 평가용 private/로 분리. 메시지·대화방·연락처 ID 통일, 번호는 섞어서 부여, 같은 분 메시지는 무작위 정렬
- 설계 결정: 고전 소설 인물 이름은 기기 안에서 평범한 이름으로 교체. 사람에겐 편한 설정이 모델에겐 "특이한 이름 = 사건 관련자"라는 정답 힌트가 되기 때문
- 트러블슈팅: 실제 규모 모의 실행에서 단체방 때문에 연락처가 이름 조합(3,000개)을 초과 → 사건 인물 이름만 유일하게 예약하고 배경은 중복 허용(실제 연락처에도 동명이인이 흔함)
- 결과: 메시지 32,194건 중 합성 130건(0.4%), 대화방 2,007개, 연락처 2,279명, 누출 검사 통과
- 중간점검: 손실 실험이 무작위 배치에선 같은 대화방 쌍이 거의 안 생겨 효과가 안 나올 설계 결함 발견 → 세 조건 비교(무작위 / 대화방 묶음 / 묶음+마스킹)로 변경 예정. 모델 실험용 검색 벤치마크를 시나리오 평가와 별도로 만들기로 함

### Step 4-1. 시간 구조 누출 대응

- 측정: 여러 날에 걸친 대화방 비율이 배경 3.5%, 합성 71.4% → 내용을 안 보고 "여러 날 대화방"만 골라도 사건 대화방이 걸러지는 누출
- 대응: 상대방 성별·연령대가 같은 AI Hub 대화 1~5개를 한 대화방의 다른 날 세션으로 묶음. 세션은 겹치지 않는 날에 배치하고 세션 안 시각은 유지
- 재측정: 배경 67.4%, 합성 71.4%. 대화방 2,007 → 828개, 연락처 2,279 → 974명(한 사람과 여러 번 대화하는 실제 휴대폰 구조에 가까워짐)

### Step 4-3. 누출 측정 도구 (대응 전 기준값)

- 측정 항목: 문체 통계, 시간 구조, 글자 n-gram 판별기(교차 검증 예측만 사용), 판별기 점수로 대화방을 줄 세웠을 때 사건 대화방 순위
- 결과: 판별기 AUC 0.974. 대화방 828개 중 1~7위가 정확히 합성 대화방 7개, 사건 대화방 4개 모두 상위 10위 안(무작위 기대 0.05개)
- 문체 차이: 평균 길이 합성 22자 vs 배경 10자, 문장부호로 끝남 72% vs 17%, 자모 0.015 vs 0.94자/메시지, 대화방 길이 18 vs 35건
- 판단: 오답 대화방 추가만으로는 판별 능력이 그대로라 희석에 그침 → 의미 보존 후처리의 소급 적용, 오답 대화방 추가, 시나리오 2·3의 생성 규칙 개선, 평가 표에 문체 판별기 기준선 포함
