# 개발 일지

날짜는 실제 작업일, Step은 개발 계획상 단계다.

## 2026-09-29

### Step 1. 데이터 확보와 공통 스키마

- 데이터 출처 결정: 배경 대화는 AI Hub 한국어 SNS(실제 메신저 대화, 비식별화), 사건 증거는 합성
- 트러블슈팅: macOS unzip이 인코딩 표시 없는 한글 파일명을 깨뜨림 → 원래 바이트를 복원해 UTF-8/CP949 순으로 디코딩하는 해제 스크립트 작성
- 데이터 조사: 비식별화 표시 분포 확인(#@이름# 11만, #@시스템#송금# 295 등) → 합성 증거도 같은 표시 형식을 쓰기로 결정
- 공통 레코드 스키마와 AI Hub 스트리밍 어댑터 구현, 무결성 해시 변조 탐지 테스트 포함
- 트러블슈팅: venv 활성화 후에도 zsh 명령 캐시 때문에 전역 pytest가 실행됨 → hash -r, python -m으로 실행 통일
- 발견: 이름순 처리로 샘플이 한 주제에 쏠림 → 주제별 층화 추출 옵션 추가

### Step 2. 시나리오 1 설계와 합성 증거 생성

- 사건 시나리오 1(중고거래 사기, 개발용) 설계와 합성 증거 생성기 구현. LLM은 문장만 쓰고, 배치·시스템 메시지·정답지 기록은 코드가 담당
- 트러블슈팅: EXAONE이 존댓말 거래 대화에서 긴 문장과 이모지를 반복 → 프롬프트 강화 대신 결정적 후처리(문장부호 분할, 이모지 제거)로 해결
- 트러블슈팅: 시나리오가 LLM에게 금지된 시스템 표시를 쓰라고 지시하는 모순 발견 → event 장면 도입, 불러올 때 거부하는 검사 추가
- 사람 검수 3회: 증거 판정 11/3/4 → 14/3/1 → 15/3/0 (통과/애매/불합격). 사람이 찾은 오류(역할 뒤바뀜, 금지어, 가짜 표시, 맥락 대화의 정답 선점 등)를 매번 검사기 규칙으로 옮김
- 검수 통과 대화방은 유지하고 문제 대화방만 재생성하는 기능 추가(대화방별 독립 난수)
- 발견: 합성 메시지에 ㅋㅋ·ㅠㅠ 같은 자모가 0자(실제는 메시지당 약 0.94자) → 문체로 합성을 구분할 위험. 가상 기기 조립 단계에서 합성 오답 대화방 확대와 판별기 측정으로 대응 예정
